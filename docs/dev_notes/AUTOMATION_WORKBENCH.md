# 自动化功能与现有界面集成

## 使用入口

启动方式不变：`python run_web.py`。登录后使用原有侧边栏和页面，不再提供独立的“自动化工作台”菜单。旧 `/static/automation.html` 链接仅负责返回主界面，保留任务深链接。

入口分布：

- 对话：消息内直接暂停、继续、接管；“结果与验证”复用原任务详情弹窗，“回放”直接打开右下角原手机窗口。
- 任务执行：沿用设备选择和指令输入，新增验收条件、队列历史及同一详情弹窗；历史画面统一在原手机窗口播放。
- 设备：设备卡片提供“录制示教”，复用现有悬浮预览；录制工具通过预览栏的“录”按钮开关，录制历史留在设备页。
- 定时任务：页内切换“定时任务／任务配方／条件触发”。“设为定时任务”复用原表单，保存配方修订、参数、忙碌策略和时区。
- 设置：运行并发、功能开关和默认时区并入原设置页。

所有入口共享原登录状态、设备选择和 WebSocket 连接，示教不另起一套预览。任务在服务端执行，关闭浏览器不会终止后续子任务。旧对话中的复杂任务与 `@设备` 分段指令也已改为一次提交整份计划。

### 对话意图与上下文

普通消息先调用当前激活模型判断 `chat / plan / clarify / execute`。问候、知识问答、方案商讨直接回复，不需要选择设备，不创建任务，不读取屏幕或解锁。只有 `execute` 才进入现有手机执行流程，复杂任务开关及 `@设备` 本身不构成执行意图。显式 `/` ADB 命令仍直接执行。

每次判断从 SQLite 读取同一会话截至当前用户消息的完整有效上下文（已完成的压缩摘要及之后的原文），包含讨论方案及历史任务结果/清单，不包含日志和图片。不再按40条或24,000字符静默截断，不跨会话拼接。后续的“按刚才方案执行”由模型消解指代。任务提交和拆解使用同一历史快照；排队后新的讨论不改变已提交任务。CLI 和手动任务入口维持原行为。

格式错误或模型故障不降级为手机操作。对话回复、模型名及 Token 用量持久化；刷新时补齐正在生成的回复。服务重启后未完成的对话显示中断，不自动补交手机任务。

### 90% 上下文自动压缩

模型配置新增 `context_window`，表示输入和输出共同占用的上下文容量，与 `max_tokens`（最大输出）区分。未配置时暂按32,768管理，界面明确提示按服务商实际值填写，不根据陌生模型名称猜测容量。跨服务商暂无统一分词器，按UTF-8字节加消息封装开销保守估算，并预留最大输出空间，界面标注为估算值。

每次模型对话前检查预算，达到90%时用当前模型分块压缩较早的内容，合并之前的摘要，保留近期原文和当前请求。原始消息、任务状态和否定约束不删除；摘要只作为背景，不能成为新的执行授权。摘要和覆盖范围持久化，进程重启后沿用。失败保留原摘要和原文，本轮请求不继续进入手机执行流程。单条当前指令本身超出预算时明确报错，不截断指令。

聊天上方展示预算、压缩中状态和累计次数；历史内的压缩记录可展开摘要、前后占用、消息范围、模型和耗时/Token信息。`GET /api/chat/sessions/{id}/context` 沿用认证，提供状态与持久化记录供刷新和轮询补齐。数据库使用独立版本表进行增量迁移，有历史消息的旧库在迁移前备份，迁移失败停止初始化。

### 任务、接管与验证

- 默认每台设备按提交顺序串行，最多两台同时执行；设置中可调整并发数。
- “停止当前后执行”只停止所选设备的当前执行，等待清理后优先运行新任务；已有排队任务保留。
- 同一任务可以在多设备上串行或并行运行。`@设备` 指令保留原有分段顺序，包括多次出现同一设备。
- 点击暂停后，等待状态变成“已暂停”再操作预览。已经提交给设备的动作允许结束；模型请求期间的暂停会使旧决策失效。
- 遇到 `Take_over` 或敏感操作确认时进入“等待接管”。手动处理后填写说明，点击继续，Agent 会重新观察页面。
- 等待人工处理不自动超时，等待时间不计入步骤的主动执行超时。超时和停止在安全边界处理，不强杀仍在使用设备的线程。
- 普通任务没有验收条件时显示“未验证”。设置验收条件后，只观察最终截图或前台应用，不通过验证器操作手机。
- 验证结论包括通过、失败、待核验；无法解析验证输出、截图不可用时不会判定通过。
- 步骤失败默认停止后续步骤。只有明确勾选“可重复执行”和“失败重试一次”才允许一次执行重试；验证失败不会自动重做操作。
- 设备离线时排队任务默认等待 30 分钟；执行期间中断或服务重启后，需要确认恢复。恢复从子任务检查点重新规划，不能当作撤销或精确重放。

### 回放

记录模型调用、截图、动作、动作结果、子任务切换、接管和验证事件。点击时间线查看对应截图及坐标标记；输入内容默认折叠。

点击手机窗口右侧“回”进入历史模式，可以选择自动任务或示教记录，播放／暂停、逐步查看、拖动进度和调整速度。点击／滑动轨迹叠加在同一个手机画面上；“实”返回实时控制，“录”打开示教工具。回放只读取记录，不启动实时流、不发送触控或按键；Home、返回、解锁等按钮在回放时禁用。

切换到回放、实时模式或关闭预览时，会暂停正在进行的示教，避免隐藏录制继续保存输入；可返回“录”继续或结束。录制结束后可以在同一窗口回放或生成可编辑配方，生成草稿仍需人工审核。

“从这里重新规划”会创建关联的新任务，保留原执行记录，不直接复用历史坐标。涉及发送、提交的步骤请先检查当前设备状态。

截图默认保存 30 天，未固定截图在总图片内容达到 2GB 时按时间清理。可固定截图或取消固定。清理后事件文字仍可查看。SQLite 释放的页供后续数据复用，数据库文件不一定立即缩小。

### 配方

配方使用顺序步骤和 `{参数名}` 占位符，参数支持文本、数字、日期、时间和枚举。每次保存创建新修订；任务保存展开后的步骤、参数和修订号，编辑配方不会改变正在运行的任务。

可以新建、复制、归档、导入导出，或从已完成任务与已编辑的复杂任务清单创建配方。多设备分段任务应先拆成单设备配方，避免携带原设备标识。试运行成功后记录设备和修订号；这表示该次试运行成功，不能保证跨设备、跨应用版本直接成功。

示例导入文件：

```json
{
  "format_version": 1,
  "name": "搜索内容",
  "parameters": [{"name": "关键词", "type": "text"}],
  "steps": [{"content": "打开浏览器搜索 {关键词}", "timeout": 180}],
  "acceptance": "页面显示搜索结果"
}
```

Telegram 支持 `/recipe` 列出配方，使用 `/recipe 配方ID 设备ID {"关键词":"天气"}` 提交。Web、定时任务、Telegram 共用同一个配方展开器和设备队列。

### 操作示教

连接预览，开始示教，然后通过 Web 预览进行点击、长按、拖动、按键，以及预览录制工具中的文本输入和包名启动操作。示教会占用设备，自动任务等待录制结束。

不捕获实体手机上的触摸，也不解析任意 shell 命令为示教动作。scrcpy 与其 ADB 输入降级路径共用录制入口。

默认不记录输入文本，默认保存关键截图用于回放，两个选项分别设置；截图可能含屏幕上可见的输入内容。H.264和ADB降级通道均在动作前通过截图适配器保存画面，不依赖JPEG缓存。旧录制未保存的截图无法追补。登录、验证码等过程可以暂停录制。暂停期间的操作不保存。

结束后先检查动作列表，再点击生成草稿。这一步才会把动作和最多 12 张关键画面发送给当前配置的模型。输入记录关闭时，草稿可能需要更多手动补充。生成的草稿需要人工检查、保存和试运行，不会立即自动执行。

### 定时与条件触发

支持设备上线、开始充电、指定配方成功结束三种条件。规则固定配方修订、参数和设备，升级绑定需要显式编辑规则。

- 服务启动时的设备初始状态不触发。
- 设备状态约每 30 秒采样；未知充电状态不构造触发边沿。
- 默认冷却 5 分钟；同一规则已有排队或运行任务时合并新触发。
- 前置任务按运行 ID 去重，禁止循环依赖。
- 执行前重新检查规则是否启用和设备条件，充电任务在等待期间拔电会取消。
- 连续三次失败停用规则，写入历史，并通过已经配置并运行的 Telegram 通道及已启用的邮件通道提醒。
- 定时配方可以选择忙碌时排队或跳过。同一定时规则不会反复堆积待执行实例。
- 时区保存为 IANA 名称；已有任务升级时沿用服务器时区，设置页可以查看默认值。修改默认时区不会改写已有计划的时区。

## 存储与运行约定

- 新数据默认存于 `~/.autoglm/automation.db`，可用 `AUTOGLM_AUTOMATION_DB` 指定隔离路径。
- 数据库通过 `PRAGMA user_version` 管理版本；已有数据库在迁移前创建 `.bak`。不支持的新版数据库直接拒绝启动。
- 旧 `chat.db` 的会话、截图和定时任务表保持原格式；新调度元数据单独保存，避免删除旧字段。
- 设备调度只能运行于一个后端进程；同一运行库上的第二个进程会被系统文件锁拒绝。
- 模型覆盖配置仅留在进程内存，任务快照不存 API Key。服务重启后的恢复使用当前有效模型配置。
- 运行设置提供功能开关。关闭入口不停止已经接受的任务；停止任务应使用任务控制。
- 停止与退出等待执行线程清理输入法和锁屏状态，然后释放设备。邮件生成与发送由后端负责，通知失败不会改写执行结论。

## API

完整请求模型见应用 `/docs`，新请求结构位于 `web_app/models/automation.py`。

| 接口 | 行为 |
| --- | --- |
| `POST /api/chat/sessions/{id}/respond` | 传入相邻用户/助手消息 ID，读取会话历史、判断意图并生成回复；此接口不操作设备 |
| `GET /api/chat/sessions/{id}/messages/{message_id}` | 补齐 HTTP 对话回复状态，检查消息所属会话 |
| `POST /api/tasks/run` | 先持久化，返回 `task_id`，再由队列执行；新客户端传 `queue: true` |
| `GET /api/tasks/{id}` | 获取父任务、设备执行、检查点、结果与验证 |
| `POST /api/tasks/{id}/pause` | 请求安全边界暂停 |
| `POST /api/tasks/{id}/resume` | 传入 `note`，继续或确认中断恢复 |
| `POST /api/tasks/{id}/stop` | 停止指定任务 |
| `GET /api/tasks/{id}/events?after=N` | 事件游标分页 |
| `POST /api/tasks/{id}/rerun` | 从 `step_index` 创建关联新任务 |
| `/api/recipes` | 配方、修订、导入导出与试运行 |
| `/api/demonstrations` | 示教开始、暂停、结束、生成草稿 |
| `/api/triggers` | 规则编辑、停用与历史 |
| `/api/automation/settings` | 并发、功能开关与默认时区 |

保留旧 `/api/tasks/run`、`/status`、`/history`、`/stop`；旧 `/stop` 仍停止全部任务。新客户端使用按 ID 停止。不存在的资源返回 404，不允许的状态转换返回 409，请求校验失败返回 422。

WebSocket 新增 `automation_event`，包含任务 ID、设备 ID、单调递增事件序号、时间和事件内容。重连使用快照和事件游标补齐；同时保留旧日志、Token 和完成事件。截图、回放及控制接口沿用现有认证。

## 前端已更新但启动时提示 Not Found

页面和 JavaScript 从磁盘读取更新，PM2 中已经启动的 Python 进程不会因此自动重新导入新路由。设备刷新成功与自动化接口返回 404 是两个独立结果。

前端现通过公开 `/health` 的 `capabilities.automation` 检查后端能力。缺少能力时只显示一次明确的重启提示，并停止自动化轮询；不会把接口缺失解释为设备未找到。登录初始化会静默刷新设备，手动刷新仍显示设备数量。服务重连可重新检查能力，后台已更新后恢复功能。

本机通过 `pm2 restart open-autoglm-gui` 加载代码更新。普通刷新浏览器不能替代重启后台服务。维护时可以创建 `~/.autoglm/.quiet-next-start`，由下次成功启动消费，仅跳过那一次启动通知，不修改已配置的通知偏好。
